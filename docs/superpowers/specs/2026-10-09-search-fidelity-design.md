# Explicit search requirement fidelity

User authorizes continuous correction and extensive real researcher-prompt tests,
not a circuit-ID or two-stage-specific patch. Continue existing feature checkout.

Root cause: model blocks were all demoted to hypotheses, so explicitly connected
structures became optional. Simple motifs ranked by fraction of circuit covered,
letting a standalone input pair outrank a complete requested circuit. The prompt's
capacitor was not independently required unless it had a numeric count phrase.

## Contract

Keep application-owned Cypher and existing providers. Add source_quote to model
required blocks and required_pattern_source to the plan. Literal positive physical
device presence creates independent minimum counts, excluding negations/preferences
and numeric constraints. Extract generic explicit wiring clauses (connected, tied,
shared, feeding/driving, between, series/parallel, terminal references); no circuit
IDs, expected results or family recipes in this extraction.

At least one connected composite pattern must cover all explicit wiring clauses
using a verbatim prompt quote, and include physical device types mentioned in that
quote. Model-authored blocks without such grounding remain soft hypotheses. Missing,
partial, optional/negative or disconnected hard interpretations trigger clarification
instead of querying a weakened request. Named standalone families, actual stage
counts and specifications remain uncertain, never presumed annotations.

## Retrieval

Hard counts/properties and grounded connected patterns filter before ranking in
both strategies. Prototype anchors must also satisfy the same eligibility checks.
Zero full matches stays zero; optional separately labelled partial results may
retain numeric/physical counts while relaxing connectivity, with missing-pattern
diagnostics. Unmatched generic function hypotheses cannot masquerade as full matches.
Use matched pattern specificity before circuit-fraction coverage for soft ranking.
No simulation, automatic metadata, ingestion, model download or remote push.

## Verification

Regression fixtures include the captured failing plan, circuit 615, an actual
complete netlist and generic RC/terminal constraints. Test missing/forged quotes,
disconnected/partial patterns, optional/negative requests, stale graph evidence,
both strategies and duplicate/invalid prototypes. Build a repeatable real-provider
audit matrix: exact existing topology/counts; available pieces without requested
connections; proven absent counts/structures; unsupported performance. Check all
returned records independently against mandatory patterns and inspect representative
original images/netlists. Evidence reports must distinguish structural evidence
from functional certification, no-source-image cases and model variance.
